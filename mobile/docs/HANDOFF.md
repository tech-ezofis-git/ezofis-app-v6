## Still open
1. **Server push (0.6.0) — to switch on:** see *Push notifications setup* below. Until then the background check (15 minutes, held while the phone is locked) is what notifies.
   - Before 0.6.0: **Server push** for instant notifications. The background check (0.5.6) runs about every 15 minutes (Android's minimum) and can be delayed by battery saving; instant alerts need the backend to register device tokens and send through FCM (Android) / APNs (iOS) when an inbox item is created.
   - **Token lifetime (backend):** access tokens last 1 day (`EzofisAuthService.AccessTokenExpiry`) and there is no refresh endpoint, so users sign in again daily and the background check stops when the token expires. Add a refresh token (or a longer-lived token for `loggedFrom: MOBILE`) and the app can renew silently.
2. **Security (backend):** the "Users" master form returns a plain-text Password column from `/form/{id}/entry/all`.
3. **Google / Microsoft sign-in:** works on Android with the debug key (README → Google and Microsoft sign-in).
   - Needs backend token verification before release.
   - Release key: register its SHA-1 in Google Cloud and its signature hash in Azure. iOS is not wired.

## Push notifications setup (Firebase)
1. Firebase project `ezofis-mobile`, Android app `com.ezofis.mobile` (debug SHA-1 34:D9:…:DB; add the release SHA-1 too).
2. `google-services.json` → `mobile/android/app/` (git-ignored: the repository is public). Rebuild; push is built in when the file is there.
3. Server key: Firebase → Project settings → Service accounts → Generate new private key. **Never commit it** (`*firebase-adminsdk*.json` is git-ignored); store it on the API server, outside the web root.
4. API settings (`appsettings.Production.json` or environment): `MobilePush:Enabled=true`, `MobilePush:ServiceAccountPath=<path to the key>` (or `MobilePush:ServiceAccountJson`), optional `MobilePush:Cron` (default every minute). Hangfire must be enabled (the job runs in the API's Hangfire server).
5. Deploy the API. In the app: sign in, Settings → Background check shows "Firebase push · On · registered with EZOFIS".
6. Test before the backend is live: copy the push token from Settings → Background check and send a test message from Firebase console → Messaging → "Send test message".

## Server behaviour seen during development
- **Errors:** GET /Workflows/{id} sometimes returned 500 or timed out; the app shows retry buttons.
- **Counts:** /Workflows/counts lags behind the lists, so the open tab's badge always shows the list's own `totalCount`.
- **CORS:** the server rejects the CORS preflight from browsers, so the web preview only works in "Explore" (sample) mode. The test APK loads from `file://`, which allows the calls.

## Testing
`tests/e2e/` holds a Python + Playwright mock of the Workflow API (`wfmock.py`, `expform.py`, shaped like the live responses with fake data) and 17 flow checks (`test_flow*.py`; 13 Ask AI, 14 Folders, 15 intelligent upload / summary / share / sign, 16 the 0.4.8 corrections, 17 the 0.4.9 round). They run against `dist-single/index.html` with every call to `https://cloud.ezofis.com/**` intercepted.

The checks print what they find rather than asserting; read the output and look for `errors []`. Screenshots go to `tests/e2e/shots/`.
